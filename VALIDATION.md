# V1 Build 12 — validation

- 133 Python regression tests pass with the actual Agent V2 Build 10 source, including eleven new permission/alias/filter cases. The real Agent validates the preference proposal, generates and signs a snapshot, and Dashboard verifies that returned envelope independently. The eleven Build 12 cases also pass against the actual Agent V2 Build 11 source.
- Eight JavaScript regression programs cover the current UI, read-only Agent permission display, disc signing instructions and explicit inventory refresh. The navigation test harness now supplies a harmless timer stub for the live signer-visibility polling introduced in Build 11.
- Permission tests cover current-state gating, exact public-policy matching independent of wallet names, disabled-offer/notification suppression, withdrawal of both peer queues, re-enabling, no Dashboard preference persistence/restore, foreign identities, wrong domains/challenges, revision rollback/conflicts and duplicate policy rejection. No new remote RPC authority is added.
- Disc-alias tests cover mismatched public route/internal Core names with matching public evidence, signing eligibility, exclusion from history before any listsinceblock request and prevention of automatic synchronization of a RAM account. Existing per-input multisig signature, policy, transfer, tax and archive tests remain passing.
- The four-policy Bitcoin Core 31 regtest and existing two-wallet PSBT composition check remain the integration checks for actual transaction acceptance. Test coins only; no user's node or wallet is operated.
- The DEB is checked for version, runtime/source parity, absence of user records/test artifacts, packaged source availability, enable/start service instructions and isolated IPv4/IPv6 web/Agent startup. It is not installed on the development laptop.

Agent owns the denial list and its persistence. Dashboard observes it; it never restores an old preference snapshot into the Agent. Physical disc hardware, production protected desktop behavior and real multi-computer approvals require deployment testing. This remains a Development build.
