# V1 Build 9 — validation

Scope: complete Dashboard support for Agent V2 Build 7's signed initial wallet previews and coordinated direct wallet synchronisation. No Agent application code or private wallet transfer path is added to the Dashboard.

- 98 Python tests passed with `WALLABY_AGENT_SOURCE` set to Agent Build 7, including actual Agent sender signature creation, receiver validation/storage in separate interpreters, and the existing Agent HTTP read-only wallet-routing integration. No tests skipped in that run.
- Five JavaScript regressions passed, covering existing Ownership/Builder behavior plus confirmed new-attempt controls, transfer outcomes, independent identity-comparison guidance and temporary synchronisation query gating.
- Signed previews use real dedicated Ed25519 test identities and OpenSSH SSHSIG verification. Tests reject changed signed facts, wrong source connections, wrong wallet policy sets, peer/challenge/transfer substitution, non-integer amounts, expiry/future timestamps and replacement of an already frozen preview. Duplicate acknowledgement/relay is idempotent.
- Scheduler tests cover alphabetic selection of one shared pair across opposite missing-wallet directions, no active-pair replacement, fresh paired nonce/address bindings, base-before-preview order and repeated base/preview delivery. Pending state, original signed snapshot and reservation survive restart.
- Transfer busy state pauses new RPC/inventory work without dropping authenticated presence or result processing. Local outcomes remain terminal. Inventory refresh resumes when both sides finish. Failed/denied/uncertain attempts are not automatically replayed; explicit retry requires local reconciliation, refreshed public inventory and a new transfer identity/challenge. Legacy Build 8 requests require deliberate new negotiation rather than a silent upgrade.
- Profile validation checks persisted preview signature and bindings without renewing its historical timestamp. Cancelled signing workflows can acknowledge local denials without reviving a job or leaving the node permanently reserved.
- Existing unsigned vault, verified partial-signature, broadcast, Core history, CGT, C1 loss and Balance Trace regressions continue to pass. A separate isolated Core 31 regtest validates the unchanged PSBT composition/signature/finalisation path with test coins.
- DEB checks verify package/source parity, excluded runtime records, automatic service enable/start, IPv4/IPv6 browser and Agent listeners, and source download. OpenSSH client is an explicit dependency for preview verification. No development-machine service is installed.

This validates protocol interoperability with the actual Agent Build 7 code. It does not claim completion of a physical two-laptop SSH transfer, real-family production CGT run, firewall configuration or human fingerprint comparison. Those deployment checks remain local to the user. The Dashboard never receives a wallet file, private key, passphrase or node cookie.
