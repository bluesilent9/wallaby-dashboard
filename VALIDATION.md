# V1 Build 8 — validation

Scope: node blockchain readiness, live vault monitoring, public Agent exchange and approval orchestration, fixed unsigned vault composition, single/multiple-wallet Agent signing and broadcast, and paired peer wallet-transfer requests. Agent code is unchanged in this release.

- 87 Python tests passed, including the current Agent V2 Build 6 read-only RPC routing integration. No skipped tests in the integration run.
- Four JavaScript regression programs passed: Ownership activity/navigation; owner/SMSF suggestions; balance tooltip/icons/fees; Build 8 component locking, shared Network Fee, readiness/signing gates and nonrecursive Vaults rendering. All bundled JavaScript parses successfully.
- Invented-key fixtures verify signatures, unchanged transactions, single-wallet completion through the common protocol, watch/private replica matching independent of names, capability gating without legacy fallback, incoming hash/schema rejection, exact pending-request/node correlation, lost-ack export retries, only explicitly open diagram bindings, and unavailable/stale node exclusion.
- Composition fixtures preserve fixed vault inputs, outputs, locktime and PSBT metadata, reject signature-bearing components, duplicate outpoints, changed fixed connections and missing ownership. Additional fee contributions include both components' conservative input/output sizes.
- Mandatory-height P2WSH cryptographic fixtures verify the key, canonical witness policy, signed amount, final witness and required locktime/sequence. Unsupported/bypass policies remain unverified rather than being labelled protected.
- An **isolated Bitcoin Core 31.0 regtest node**, with network peers disabled and invented test coins, created two unsigned PSBT components, including a vault output. Dashboard combined them before signing; each Core wallet signed only its own input. Dashboard verified both partial results, finalised the combined transaction, and Core accepted and broadcast it on isolated regtest (two inputs, two outputs, 2,000 sats fee). No production wallet/node was used.
- Vault fixtures cover green unexpired, red unlocked and amber missing policy authorisation, with two-unit countdowns. Public policies ignore origin annotations for matching, retain actual scripts/branches, and are included in portable profile data.
- HTTP fixtures verify authenticated exchange, denied browser origins/missing tokens, duplicate JSON field rejection and legacy-compatible response shape. Peer transfers remain public-manifest orchestration only, with IPv6 hints and local approval capability checks. No remote wallet-writing/signing/broadcast RPC methods are added.
- Existing trace, CGT, C1 loss, deferred price, historical-wallet grouping and Node loading regressions continue to pass. Exact historical outpoint maps are used for Builder ownership; economic C1 records cannot become fake on-chain inputs.
- DEB package validation checks source/package parity, excluded runtime records, systemd enable/start in postinst, IPv4/IPv6 browser and Agent listeners, and the source-code download. The DEB is not installed on this development machine.

The real family node was not used for a fresh production run. End-to-end local Agent authorisation for the new capabilities waits for the separately planned Agent update. There is no assertion that old Agents already support those capabilities or can merge already signed transactions safely. Existing annual CGT/parcel conventions are unchanged.
