# Build 30: independent queues and authenticated preview notices

The reported logs contain repeated `A frozen preview cannot be replaced` and `Unsolicited preview or not the paired sending Agent` errors. Either rejected the whole exchange and prevented normal reply/queue progress. A signed public preview notice is not a transfer result: after verifying its signature, exact issued request, sending node, descriptors, challenge and endpoints, an inactive/late notice can be acknowledged without activating a transfer. A changed signed notice cannot overwrite the frozen snapshot. A changed signer identity is still rejected. Changed facts require local reconciliation and a deliberate fresh attempt. The existing confirmed retry action is available for an unattempted changed snapshot; it preserves the old evidence and creates a new transfer/challenge rather than replacing the approved snapshot. History recovery or partial operation outcomes remain ineligible for this shortcut.

Cryptographic validation accepts historical timestamps only to classify an already-issued notice. First activation still requires the normal freshness window. Obsolete historical notices retain their separate grouped-container checks. No transaction result, wallet deletion result or received-but-history-incomplete outcome is discarded.

Each destination retains its own full authoritative wallet list. Fifteen previews previously advanced the cursor by fifteen before the final response was reduced to sixteen total messages; mandatory control messages could cause the same final previews to be omitted forever. The cursor now advances by the actual number delivered. Control queues and signing/retirement messages precede optional preview copies.

Diagnostics log changed queue revisions, send and receive counts and ignored notice categories. Payloads and credentials are excluded and existing bounded seven-day retention applies. Genuine simultaneous hostname/MAC conflicts remain errors. Agent V2 Build 26 independently handles a late preview for a locally disabled incoming request without re-enabling it.
