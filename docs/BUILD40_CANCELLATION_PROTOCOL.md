# Build 40 Dashboard → Agent handoff

## Existing protocols: no Agent change required

Rename uses the existing wallet_rename_v1 full queue. Cancelling any unfinished rename withdraws remaining requests, while completed and uncertain signed results remain recorded. Late success must not resurrect a cancelled operation. A newer cancelled operation that already applied/attempted a rename blocks older filename enforcement; no rollback is invented.

Make Extinct uses wallet_retirement_v3 and wallet_retirement_cancel_v1. The Dashboard permits cancellation only while matching private-key accounts are connected. Every multisig signing role must be identifiable, even if the threshold could be met with fewer. Watch-only data, duplicate copies of the same key and a multi-key public descriptor without proven signing accounts do not establish all roles. Public getwalletinfo/listdescriptors(false) reads recheck eligibility on submit. Existing Agent-local cancellation remains authoritative for delivered operations. Completed deletion is not undone, and distinct missing keys cannot be regenerated by sync. Synchronisation is released only once pending cancellation outcomes resolve. Direct wallet deletion remains Agent-only.

## New capability required: wallet_archive_cancel_v1

Advertise this alongside wallet_archive_queue_v1. The existing wallet_archive_queue version 1 envelope gains an archive_cancel task kind. Dashboard sends that kind only to an Agent advertising the new capability. Older Agents receive withdrawal of the original request but the Dashboard retains the cleanup task and explicitly reports the update requirement.

An archive_cancel task has EXACT fields:

- kind: archive_cancel
- version: 1
- nonce: random 64-character lowercase hex
- request_id: SHA-256 of canonical JSON of all other fields, as for existing archive tasks
- wallet: the original request wallet route/name
- archive_request: the exact original archive_wallet task, including its request_id
- completed_receipt: the original Agent signed_receipt if completion was known when cancelled; otherwise null
- finish_inflight_burn_and_verify: true
- require_local_destruction_confirmation: true
- preserve_unrelated_members: true

Bind the task to the original exact request identity and local artifact records, not merely its mutable wallet name or matching descriptor. A fresh archive request for the same wallet is a distinct operation and must not be discarded by an old cancellation. Reconciliation is required if local artifact outcome is uncertain. A null completed_receipt is not proof that no disc exists: a burn can complete after cancellation is queued. Agent must check its own in-flight/staged/completed records, authenticating any supplied original receipt and checking its paired source identity and original request binding. For reassigned completed-disc work, independently verify the matching loaded package as described below.

Unused request: remove it and unused staging safely; no disc was created. Started burn: do not interrupt writing or readback. Finish both, including handling failed verification, then request local physical cleanup. Completed burn: request local cleanup. Shared disc: retain all unrelated members, making and verifying a replacement first if required. Multiple cancellation tasks in one burn can share physical evidence, but every requested task must retain its own signed outcome. All physical copies/partially written discs belonging to that operation must be accounted for. Dashboard does not authorise destruction or handle private wallet files.

## Result: existing archive_queue_result outbox

Use the existing exact signed-receipt wrapper, paired Agent identity, version, queue_id and request_id binding. queued/error keep the cancellation task pending. Use status=complete only after local resolution, with:

- request_cancelled: true
- disc_created: boolean (explicit, not omitted)

If disc_created is true, also require:

- archive_id: lowercase 64-character public package identity, matching a known original completion if one exists
- disc_count: positive integer, number of created physical discs associated with the operation
- destroyed_disc_count: equal to disc_count, confirmed locally
- burn_finished: true
- verification_finished: true (the verification attempt finished; it need not have passed for a bad disc to be destroyed)
- destruction_confirmed_locally: true
- unrelated_members_preserved: true
- replacement_required: boolean, plus replacement_readback_verified:true and replacement_image_sha256 (64 lowercase hex characters) whenever required

A Dashboard-known verified completed archive cannot later be claimed as no disc created. Deleting the local cancellation review is not completion: return error/pending for reconciliation, never deleted/complete as an invented physical outcome. Identical signed completion retries are idempotent; changed terminal outcomes and wrong-Agent reports are rejected.

Dashboard cancellation completion appears as a red cancellation notice. Successful original archive completion remains green. Only pending tasks occupy the combined Wallets table. Cancellation tasks, exact parent requests, signed outcomes and rename history survive profile save/restore.

## Validation limits

Dashboard tests cover visibility guards, endpoint rechecks, partial/late rename results, queue identity, capability gating, no-artifact outcomes, completed/racing burns, all-copy cleanup counts, replacement safeguards and combined UI. Current Agent Build 30 does not implement this new task; end-to-end burn/cancel/destruction testing must run after its update. No physical disc was destroyed in Dashboard tests.

## Remembered nodes and portable disc reviews

Deleting a remembered node requires that it is disconnected. This forgets its Dashboard route and removes its pending obligations, without deleting remote wallets or claiming that a local task succeeded. Completed receipts, filename history and public wallet evidence remain stored. An interrupted key-producing ceremony retains its evidence and requires local reconciliation.

Completed-disc cancellation and disc-destruction reviews can be reassigned to a compatible Agent with that exact archive loaded. The original completed receipt may belong to another paired Agent: the receiving Agent must independently verify the loaded archive ID, package members and original request binding, and obtain local authorisation. Dashboard names alone are never destruction evidence. Unknown or in-progress burns stay with the original Agent and cannot migrate. Extinction-disc rerouting requires current verified preservation evidence; a changed preservation proof produces a fresh request binding.

The new `wallet_archive_cancel_v1` capability must therefore cover both locally originated requests and these verified completed-disc transfers. The Dashboard retains an unassigned review until an eligible Agent is selected. Forgetting a node never proves that a physical disc was destroyed.
